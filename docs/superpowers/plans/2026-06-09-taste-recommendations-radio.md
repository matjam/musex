# Taste Profile, last.fm Love-Sync, Smart Playlists, Radio — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Design approved in conversation 2026-06-09 (this header is the spec).

**Decisions (user-confirmed):** early skips derank *a little*; ratings 4–5★ map to last.fm loved (below/cleared → unloved); radio is **host-owned** — plugins only *suggest* tracks (no `ctx.player`); Lidarr and the AI recommender are OUT of scope (the `TrackRecommender` extension point they'll use IS in scope).

**Design summary:**
- **Taste profile (main, host-owned):** an incrementally updated, persisted profile fed by the playback monitor + rating writes. Per-artist affinity score (full play +1, early skip −0.3, track rating contributes `(stars−3)×1.5`, direct artist rating ×2) with exponential decay (half-life 90 days, applied lazily from `lastSeenMs` with injected `now()`); per-track stats (`plays`, `skips`, `lastPlayedMs`) keyed `lower(artist)␟lower(title)`. Caps: 500 artists / 2000 tracks (drop lowest |score| / oldest). Pure logic in `packages/desktop/src/logic/taste-profile.ts` (tested); persistence via electron-store file `listening-profile`.
- **Signals:** "full play" = the scrobble-gate pass (already computed); "early skip" = `trackEnded` with `playedSec < 60` AND `< 25%` of duration; in-between = neutral. New host event `trackRated { track: TrackInfo, rating10: number | null }` (emitted from the rate IPC when the renderer supplies the TrackInfo — track ratings only; artist ratings feed affinity directly, no plugin event).
- **Plugin API (additive — apiVersion stays 1):** `PluginEvents.trackRated`; `ctx.library.topArtists(limit?)`; `SectionContext.topArtists: {name, score}[]`; `ctx.registerTrackRecommender(r)` with `TrackRecommender { id; recommend(ctx: RecommendContext): Promise<RecommendedTrack[]> }`, `RecommendContext { seedTracks: {title, artist}[]; seedArtists: string[]; exclude: {title, artist}[]; count: number }`, `RecommendedTrack = { artistName: string; title?: string }` (title absent = artist-level suggestion).
- **last.fm:** toggle "Love tracks rated ★★★★ or more" (default on): `trackRated` rating10 ≥ 8 → `track.love`; rating10 < 8 or null → `track.unlove` (only when connected + toggle on; failures logged). Recommender: `track.getSimilar` per seed track (+ `artist.getSimilar` as artist-level fallback), connected-only.
- **Smart playlists (local, canned v1):** sidebar section "Smart" above Playlists with three entries — **Top Rated** (library tracks rating ≥ 8, sort rating desc), **Heavy Rotation** (top track-stats by decayed play count), **Rediscover** (tracks with plays or rating ≥ 8 whose `lastPlayedMs` > 60 days, high-affinity first). Computed on open: Top Rated filters `listAllTracks` (cached) client-side; the other two join main's stats (IPC) against library tracks by artist+title (case-insensitive).
- **Radio (host-coordinated, renderer-applied):** renderer radio mode (state in PlayerProvider): started from a track ("Start Radio" in the track context menu) or artist (artist page ⋯ menu). While active, when upcoming queue < 5 tracks → IPC `radioNext` → main fans out to recommenders (10s timeout, per-plugin try/catch), merges + dedupes against `exclude`, resolves suggestions against the **library** (gateway.search by `artist title` / artist name; exact-ish case-insensitive title+artist match for track suggestions, any not-excluded track of a matched artist for artist suggestions), returns real playable `Track[]` (proxy-baked thumbs) → renderer `enqueueEnd`s them. Radio indicator + off-toggle (lucide `Radio`) in the queue drawer header; radio turns off on manual `loadQueue` (playing something else).

### Task 1: `trackRated` event + last.fm love-sync
- `packages/plugin-api`: add `trackRated: { track: TrackInfo; rating10: number | null }` to `PluginEvents`.
- Rate IPC: `rateItem` args gain optional `trackInfo?: TrackInfo`; renderer call sites that rate TRACKS (TrackRow, NowPlayingBar, TrackDetailPanel via `state/ratings.tsx`'s `rate()`) pass it (add `trackInfo` to the `rate()` args; artist ratings omit it). Handler: after a successful `rt.gateway.rateItem`, if `trackInfo` present → `rt.plugins.emitEvent("trackRated", { track: trackInfo, rating10: args.rating })`.
- `plugins/lastfm`: settings schema gains `{ kind: "toggle", key: "loveOnRating", label: "Love tracks rated ★★★★ or more" }` (default on, `!== false` like scrobbling); subscribe `trackRated`: connected + toggle on → rating10 ≥ 8 ? `track.love` : `track.unlove` (artist, track params; log failures, no toasts, no retries). Rebuild (`pnpm build:plugins`).
- Tests: none new beyond green suite (event plumb is covered by host fan-out tests); manual: rate 4★ → loved on last.fm, drop to 3★ → unloved.
- Commit: `feat(ratings): trackRated plugin event; last.fm loves 4★+ tracks`

### Task 2: Taste profile
- `packages/desktop/src/logic/taste-profile.ts` (+thorough tests, TDD): pure `TasteProfile` class over a plain serializable state `{ artists: Record<string, ArtistStat>, tracks: Record<string, TrackStat> }` with injected `now()`. API: `recordPlay(track, kind: "full" | "skip" | "partial")`, `recordTrackRating(track, rating10|null)` (delta vs the previous rating contribution — store last rating contribution per track OR recompute simply: keep `ratingStars` on TrackStat and apply score delta), `recordArtistRating(artistName, rating10|null)` (×2 weight), `topArtists(limit)` (decayed score desc, positive only), `trackStats()` accessor, `serialize()/load()`. Decay: on each artist update, `score = score * 0.5 ** ((now - lastSeenMs) / 90days)` before adding the delta; `topArtists` applies read-time decay too. Enforce caps.
- Wire into `playback-monitor.ts` (it already sees full-play/ended): classify skip (`playedSec < 60 && playedSec < 0.25 * durationMs/1000`), full = scrobble-gate pass, else partial (+0.1? No — neutral, record lastPlayed only). Persist via persistence accessors (`listening-profile` store file, debounced/throttled saves ~5s like the cursor).
- Rate handler also calls `rt.tasteProfile.recordTrackRating/recordArtistRating` (artist when no trackInfo? artist ratings come with itemId only — pass artistName: extend rate IPC args with optional `artistName?` from ArtistDetailView).
- `ctx.library.topArtists(limit)` wired in runtime deps; `SectionContext` gains `topArtists` (plugin-api + host getSections context build — keep recentArtists/recentTracks). Discover seeding: lastfm similar-artists provider now seeds from `sectionCtx.topArtists` (fallback recentArtists). Rebuild plugin.
- Commit: `feat(taste): persisted listening profile — affinity scoring, decay, topArtists for plugins`

### Task 3: Smart playlists
- IPC `getTrackStats` → `{ key, plays, skips, lastPlayedMs, decayedPlays }[]` from the profile (main computes decayed values).
- Renderer: View union `{ name: "smart"; kind: "top-rated" | "heavy-rotation" | "rediscover" }`; sidebar "Smart" section (lucide `Sparkles` for the header; entries: `Star`, `Flame`, `History`) above Playlists; `SmartPlaylistView`: fetches `listAllTracks(libraryId, "title")` (cached) + `getTrackStats`, computes the canned list per kind (rules in a pure, tested `renderer`-importable helper `packages/desktop/src/logic/smart-playlists.ts`: takes tracks + stats + now → Track[]), renders header (name, count, Play + Shuffle buttons like TracksView) + `VirtualTrackList` with the standard TrackRow wiring (select/activate/menu).
  - Top Rated: `userRating >= 8`, sort rating desc then artist/title. Heavy Rotation: join stats by `lower(artist)␟lower(title)`, decayed plays desc, top 100, plays ≥ 2. Rediscover: (rating ≥ 8 OR plays ≥ 3) AND (`lastPlayedMs` absent or > 60d old), affinity-weighted shuffle-ish order (sort by artist affinity desc — pass `topArtists` scores in), top 100.
- Commit: `feat(playlists): smart playlists — Top Rated, Heavy Rotation, Rediscover`

### Task 4: Recommender extension point + host radio resolution + last.fm recommender
- plugin-api: `TrackRecommender`/`RecommendContext`/`RecommendedTrack` + `ctx.registerTrackRecommender` (registry array like the others; Disposable).
- Host (`plugin-host.ts` or surfaces): `recommendTracks(ctx: RecommendContext)` — fan-out (10s timeout, isolation), merge, dedupe by `lower(artist)␟lower(title)` and against `exclude`.
- Main IPC `radioNext({ seedTracks, seedArtists, exclude, count })` → recommenders → **library resolution** in a tested pure-ish helper: for each suggestion, `gateway.search(lib, title ? `${artistName} ${title}` : artistName, token)`; track suggestions need case-insensitive artist+title match in `results.tracks`; artist suggestions pick up to 2 not-excluded tracks by that artist from `results.tracks`. Cap to `count`, bake thumbs (`rt.proxy.artUrl`), return `Track[]`.
- `plugins/lastfm`: `registerTrackRecommender` — for up to 3 `seedTracks`: `track.getSimilar(artist, track, limit 10)` → `{artistName, title}` suggestions; plus `artist.getSimilar` of `seedArtists[0]` (if any) → artist-level suggestions; connected-only; per-call try/catch. Rebuild.
- Commit: `feat(radio): TrackRecommender extension point, host-side resolution, last.fm recommender`

### Task 5: Radio mode (renderer)
- `player.tsx`: `radio: { active: boolean; seedTracks: {title, artist}[]; seedArtists: string[] } | null` state + API `startRadioFromTrack(track)` (plays it via `playTrackNext` if not already current, sets radio state), `startRadioFromArtist(name)` (just arms radio with the artist seed; queue continues), `stopRadio()`. Auto-append effect: radio active && queue exists && `tracks.length - index - 1 < 5` && not already fetching → `radioNext` with seeds + exclude = current queue tracks + last 20 recently played (`{title, artist}` mapped) → `enqueueEnd(result)`; if result empty twice in a row, stop radio + toast-ish console (use plugin notify? no — simple: stop silently, log). Manual `playTracks`/`playTracksShuffled` (new collection) → `stopRadio()`.
- UI: track context menu "Start Radio" (lucide `Radio`) above the plugin actions; artist page ⋯ menu gains "Start Artist Radio"; queue drawer header shows a `Radio` icon chip + "Radio on" with an X/toggle to stop when active (pass radio state via usePlayer).
- Commit: `feat(radio): radio mode — seeded auto-extending queue, start from track/artist, queue-drawer control`

**Manual acceptance (end of arc):** rate 4★ → loved on last.fm (3★ → unloved); play/skip some tracks → Discover's "Because you listened to" reflects real favorites; Smart lists populate sensibly; Start Radio on a track → queue keeps refilling with related library tracks, stops when toggled off or replaced.
