# musex — Project Instructions

A macOS (Electron) music player that streams from Plex, with planned external-metadata search, AI-driven discovery (user-supplied inference API key), and Lidarr integration to acquire discovered music. Spotify-like experience over the user's own Plex library. Mobile (React Native) + CarPlay/Android Auto are future targets sharing the same core.

## Git workflow (OVERRIDES global CLAUDE.md)

- **Remote:** `git@github.com:matjam/musex.git`
- **Feature branches + PRs (since 2026-06-10 — `main` has branch protection; direct commits to `main` no longer work).** No issue tracker; name branches `feature/<short-description>` / `fix/<short-description>`.
- **Group logical sets of features into a single PR** — e.g. a batch of UI improvements is ONE branch/PR, not one PR per tweak. Don't split related work.
- **PR titles MUST be conventional commits (`feat: …` / `fix: …` / `chore: …`).** PRs get squash-merged and the repo is configured (`squash_merge_commit_title=PR_TITLE`, 2026-06-11) to use the PR title as the squash commit subject — a non-conventional title makes release-please see NOTHING releasable. Why: PR #7 ("Taste expansion: …") squashed away all its `feat` commits and no release PR appeared; fixed with an empty `feat:` commit (#8).
- Push after every commit (`git add -A` always — never selective staging).
- **Releases:** when a work arc is done and merged, cut a release by merging the open release-please PR (only when the user asks). **Version semantics (since 0.1.3): `feat:` bumps MINOR, `fix:` bumps PATCH, breaking changes also bump minor while pre-1.0** (`bump-patch-for-minor-pre-major: false`, `bump-minor-pre-major: true`).

## Architecture (decided 2026-06-08 — see `docs/superpowers/specs/`)

- **Hexagonal / ports & adapters.** A pure, platform-agnostic `@musex/core` (domain models, use-cases, `PlaybackSession` state machine, port interfaces — **no Node, no DOM, no Electron imports**) sits in the middle. Every surface (Electron desktop, future React Native, CarPlay, Android Auto) is a thin adapter over the core.
- **Pure logic lives in `packages/core/src/logic/` (Phase 0 of the mobile roadmap, 2026-06-11; spec `docs/superpowers/specs/2026-06-11-phase0-core-refactor-design.md`).** collage, discography-merge, external-url, for-you, genres, library-sort, library-watch, list-validator, mood-mixes, nav-history, plex-mapping, smart-playlists, taste-expansion, taste-profile — all re-exported through the `@musex/core` barrel (NEVER deep-import core). Desktop's `src/logic/` keeps ONLY platform-coupled modules: `cache` (node:crypto), `scrobble-gate` (plugin-api TrackInfo — core keeps zero deps), `mpv-ipc`, `audio-filters`, `proxy-url`, `plugin-manifest`. **Core's purity is compiler-enforced:** `lib: ["ES2022"]` + a minimal `src/globals.d.ts` declaring exactly the host globals core uses (`URL` four members, `structuredClone`) — do NOT add the DOM lib (it would let `fetch`/`window` typecheck); the globals file doubles as the React Native polyfill manifest (Hermes lacks full URL). New pure logic goes in core unless it imports Node/Electron/plugin-api.
- **Electron process split:** `main` is the "data plane + audio output" (Plex HTTP — Node avoids Plex's missing CORS headers — Keychain token storage, localhost stream proxy, typed IPC, and the vendored-mpv playback engine). `renderer` is the "UI plane" (React UI; hosts the core `PlaybackSession`, which drives main's mpv through the `IpcPlaybackEngine` port adapter — the renderer plays no audio itself).
- **Streaming:** everything **direct-plays the original file** — mpv (ffmpeg) decodes every codec Plex can store, so there is NO transcode path. Audio is **proxied through main** so the Plex token never reaches the renderer (proxy supports HTTP range requests for seeking).
- **Two caches, both in main, both behind ports/decorators (core stays pure):** (1) **Media cache** — `MediaCache` + the stream proxy write through played direct-play files to `userData/media-cache/` (LRU, opt-in via Settings). (2) **List cache** — `CachingPlexGateway` decorates `PlexapiGateway` (it's what `Runtime.gateway` instantiates; also delegates the non-port `endpoint()`); caches item-heavy lists (`listArtists/listAlbums/listTracks/listPlaylistTracks`) to `userData/list-cache/` (`ListCacheStore`, JSON-per-key, evicting). **Invalidation is exact, not TTL:** the renderer passes a `validator` (`listValidator(updatedAt, count)` from `src/shared/list-validator.ts`) built from the parent's Plex `updatedAt`(+`leafCount`) it already holds; cache hit returns with no Plex call, mismatch refetches. Playlist mutations evict `pltracks:{id}`. `search` is never cached (live); the top-level library artists list is currently uncached (no cheap parent validator). Long playlists load **progressively** (`useProgressiveList` + `listPlaylistTracksPage`, container paging via `server.query()` with `X-Plex-Container-Start/Size` in the path — `fetchItems`' `options` arg is client-side filtering, NOT URL params). Track lists render **virtualized** via `@tanstack/react-virtual` (`VirtualTrackList`). Note: a CSS `transform` on virtual rows means any `position:fixed` child anchors to the row, not the viewport — so context menus/modals are rendered at the view level, outside the virtualized rows. **Prefetch (gated on cacheEnabled):** the renderer sends `[current, ...next 10]` on queue change; `StreamProxy.prefetch` downloads them **strictly sequentially (concurrency 1), current track first** — priority + politeness (a parallel prefetch competing with the live stream starved playback), and it's the ONLY thing that caches the current track (mpv streams with Range requests, which the serve path never caches).

- **Audio + art stream proxy — localhost Node `http.Server` (NOT `protocol.handle`).** The custom-scheme + `net.fetch` approach was ABANDONED after a long fight: gapless-5/hls.js load via XHR, which Chromium first blocks on a custom scheme (CORS: "only supported for chrome/http/https…" — needs `corsEnabled`), then once past that, `net.fetch`'s body re-streamed through `protocol.handle` **truncated large responses mid-stream** (`net::ERR_FAILED` ~1.25MB in), and buffering the whole body to dodge that broke playback start (user-activation window lapses) + hit `net::ERR_CONTENT_LENGTH_MISMATCH`/`503` under concurrent load. The robust fix: a Node `http.Server` on `127.0.0.1:0`; main pipes to Plex via `http`/`https` (Range/206 native, no buffering), injecting `X-Plex-Token`. `resolve()`/`artUrl()` bake full `http://127.0.0.1:<port>/<secret>/<serverId><plexPath>` URLs into the data handed to the renderer over IPC — so `<img>`/`<audio>` all just work (http is first-class; no scheme-CORS, no preflight weirdness). (Playback now happens via vendored mpv in main — see the audio-engine note below — but the proxy URLs and art `<img>` loading are unchanged.)
- **Stream-proxy security (token-injecting loopback service — REQUIRED, flagged by security review):** never `Access-Control-Allow-Origin: *`. Gate every request with (1) a **per-launch random secret** carried in the URL **path** (a header won't work — `<img>`/`<audio>` can't set headers; a query param won't survive HLS relative-segment resolution), (2) **`Host === 127.0.0.1:<port>`** (DNS-rebinding defense), (3) reflect the renderer `Origin` only AFTER those checks. Only main knows the secret; it bakes it into the URLs. Without this, any local web page could stream the user's Plex library through the token-injecting proxy.

- **Startup connection caching (2026-06-09) — `resource.connect()` is SLOW (~10s).** `@ctrl/plex`'s `resource.connect()` probes the server's connection URLs (local/remote/relay/`.plex.direct`) and took ~10s **every launch** (in-memory only) — the bulk of a ~22s cold start (made worse because the library wasn't persisted, so the whole discovery ran inside the "Restoring session…" splash, ×2 from React StrictMode in dev). ## Conventions

- **Prior art first — don't roll our own.** Use mature, maintained libraries for hard sub-problems (Plex API, gapless playback, HLS, secure storage, etc.) and wrap each behind a core-owned port so it can be swapped. Candidates so far: `@ctrl/plex` / `@lukehagar/plexjs` (Plex), `@regosen/gapless-5` (gapless), `hls.js` (HLS), Electron `safeStorage` (token), `electron-store` (state).
- **TDD.** Core is the primary test target, exercised against fake ports (`FakePlexGateway`, `FakeTokenStore`, `FakePlaybackEngine`). One opt-in integration smoke test against a real Plex server, env-gated (`MUSEX_PLEX_E2E=1`); not in normal CI.
- **Local bar = CI bar:** run tests + lint + typecheck + format-check before every push.
- No silently swallowed errors (empty `catch {}` is a bug). 401 from Plex → drop to signed-out and re-auth, don't loop.
- **Icons: always `lucide-react` (the project icon package). No emoji in the UI** — transport controls, nav, buttons, etc. all use lucide icons for a consistent look. If a spec/mockup shows an emoji glyph it's shorthand; implement it with the matching lucide icon.
- **License/attribution (2026-06-10): repo is MIT (LICENSE + README).** The About window (app menu → About musex; renderer `AboutModal`, opened via `navigateTo {view:"about"}`, works signed-out) shows version + a scrollable attribution list from `packages/desktop/src/renderer/src/generated/licenses.json` — COMMITTED + biome-excluded (`!**/generated/**`), regenerate with `pnpm gen:licenses` **whenever runtime dependencies change** (`scripts/generate-licenses.mjs`: pnpm licenses -P + manual react/react-dom/electron/mpv entries; lazy `import()` keeps the 84KB out of the startup bundle). Renderer gets the app version via vite `define` `__APP_VERSION__` (declared in `vite-env.d.ts`). mpv ships GPL-2.0-or-later as a separate binary — keep its source attribution in README + About if anything about its bundling changes.
- **Every file in the packaged app MUST be owner-writable (auto-update breaks otherwise).** Squirrel.Mac's ShipIt strips quarantine xattrs from EVERY file of an update, which needs owner-write; ONE read-only file → "Permission denied" → install aborts after 3 attempts → old version relaunches and re-prompts forever (electron-updater logs look fully successful — the failure is only in `~/Library/Caches/net.stupendous.musex.ShipIt/ShipIt_stderr.log`). Why: mpv ships `libMoltenVK.dylib` mode 444; broke ALL auto-updates (diagnosed 2026-06-11). Fix: `scripts/fetch-mpv.mjs` chmods the vendor tree `u+w` + `packages/desktop/build/ensure-writable.cjs` (electron-builder `afterPack`, pre-sign — mode bits aren't sealed by signing) chmods the whole packed app.
- **Native/binary runtime dependencies are ALWAYS bundled — never assume a system/homebrew install.** Anything the app needs at runtime (e.g. mpv/libmpv) must be provisioned by a repo build step — pinned version, checksum-verified, committed script, output in `vendor/` (gitignored) — and packaged into the app (electron-builder `extraResources`). **Dev mode uses the same vendored artifact** as the packaged app, so dev and prod can't diverge. Why: the app must run on a fresh machine with no setup; "brew install X for dev" was explicitly rejected (2026-06-09). **Exception — Linux (2026-06-12): mpv is a SYSTEM package on Linux** (the .deb `Depends: mpv`; AppImage users install it). Rationale: Linux has package managers (macOS didn't, which is why macOS bundles), and bundling mpv's full `.so` closure portably is far harder than the system dep. This exception is Linux-only — **Windows will still bundle mpv.exe** when it's added.
